How Node.js Works

  1. JavaScript code is written.
  2. V8 Engine converts JavaScript into machine code.
  3. Node.js executes the code.

  6. Completed results are returned using callbacks, promises or async/await.
Node.js is Single Threaded but it can handle many users simultaneously using the Event Loop and asynchronous programming.

S.No Method Description

1. Browser Console (console.log())

Before learning Node.js, we usually execute JavaScript inside the browser. Every modern browser provides Developer Tools where we can write JavaScript.

Steps:
  1. Open Google Chrome.
  2. Press F12 or Ctrl + Shift + I.
  3. Open the Console tab.
  4. Write JavaScript code.
console.log("Hello World");

console.log(name);
This method is mainly used for learning JavaScript and debugging browser applications.

2. REPL (Read Eval Print Loop)

REPL is an interactive environment provided by Node.js. It allows you to execute JavaScript code line by line without creating a file.

REPL Full Form
  • R → Read
  • E → Evaluate
  • P → Print
  • L → Loop
How to Open REPL?
  1. Open Command Prompt or Terminal.
  2. Type node.
  3. Press Enter.
  4. Now the terminal becomes a JavaScript environment.
C:\Users\User> node

> 10 + 20

> let age = 22

undefined

> age

How to Exit REPL?
  • Press Ctrl + C two times.
  • Or type .exit and press Enter.
When do we use REPL?
  • Quick testing of JavaScript code.
  • Learning JavaScript concepts.
  • Debugging small pieces of code.
  • Practicing Node.js commands.

    // Store incoming data
    let data = "";

    // Called when response is complete
    res.on("end", () => {
        JSON.parse(data);
    });

    // Handle errors
    res.on("error", (error) => {
        console.error(error);
    });

});

Node.js Modules (CommonJS & ES Modules) - Quick Revision

1️⃣ What is CommonJS?

CommonJS is the default module system used in Node.js (before ES Modules). It uses require() to import modules and module.exports to export data.

Export
// math.js

function add(a,b){
    return a+b;
}

function multiply(a,b){
    return a*b;
}

module.exports = {
    add,
    multiply
};
Import
const { add, multiply } = require("./math.js");

console.log(add(2,2));

2️⃣ What are ES Modules (ESM)?

ES Modules are the modern JavaScript module system. They use export and import keywords.

Export
export function add(a,b){
    return a+b;
}

export function multiply(a,b){
    return a*b;
}
Import
import { add, multiply } from "./math.js";

console.log(add(5,5));

3️⃣ Default Export

  • Only one default export is allowed per file.
  • Can be imported using any name.
// Export
export default function add(a,b){
    return a+b;
}

// Import
import adding from "./math.js";

console.log(adding(2,2));

4️⃣ Named Export

  • Multiple named exports are allowed.
  • Must be imported using the exported name.
// Export
export function add(){}
export function subtract(){}

// Import
import { add, subtract } from "./math.js";

5️⃣ Aliased (Renamed) Import

Use the as keyword to rename a named export while importing. 

import { subtract as s } from "./math.js";

console.log(s(10,5));

6️⃣ Import Entire Module

Import all exported members as a single object using * as. 

import * as math from "./math.js";

console.log(math.add(2,2));
console.log(math.subtract(5,2));
console.log(math.multiply(4,2));

Express.js is a fast, lightweight, and flexible web framework built on top of Node.js. It helps developers build web applications and REST APIs with less code.

Interview Answer:
Express.js is a minimal Node.js framework that provides features like routing, middleware, request handling, and response handling, making backend development faster and easier.

2. Why Express.js Instead of Node.js?

Node.js Express.js
Runtime Environment Web Framework
Need to manually create routes Simple routing methods like app.get()
More boilerplate code Less code, faster development
Need to manually parse requests Built-in middleware support
Suitable for low-level development Best for APIs and web applications
Interview Answer:
We use Express.js because it reduces boilerplate code and provides built-in features like routing, middleware, request handling, and response handling, making backend development faster than using only Node.js.

3. Alternatives to Express.js

Framework Description
NestJS Enterprise-level framework built with TypeScript.

Express.js CRUD Operations

Below is a simple Express.js CRUD example demonstrating GET, POST, PUT, PATCH, and DELETE operations. 

import express from "express";
import path from "path";

const app = express();

// auto parse json body
app.use(express.json());

let users = [
  { id: 1, name: "sainath" },
  { id: 2, name: "venu kumar" },
  { id: 3, name: "veda" },
];

// home route
app.get("/users", (req, res) => {
  res.send(users);
});

// post new users.
app.post("/addUsers", (req, res) => {
  const payload = { ...req.body };

  users = [...users, payload];

  res.status(201).json({
    message: "Added new user",
    username: payload.name,
  });
});

// put method

app.put("/replaceUser/:id", (req, res) => {

  const payload = { ...req.body };

  const { id } = req.params;
  const userId = parseInt(id);

  const userIndex = users.findIndex((item) => item.id === userId);

  if (userIndex === -1) {
    return res.status(404).json({
      message: "No user found"
    });
  }

  users[userIndex] = {
    id: userId,
    ...payload
  };

  res.status(200).json({
    message: "Replace user successfully"
  });

});

// patch method

app.patch("/updateUser/:id", (req, res) => {

  const payload = { ...req.body };

  const { id } = req.params;
  const userId = parseInt(id);

  const userIndex = users.findIndex((item) => item.id === userId);

  if (userIndex === -1) {
    return res.status(404).json({
      message: "No user found"
    });
  }

  users[userIndex] = {
    ...users[userIndex],
    ...payload
  };

  res.status(200).json({
    message: "Updated user successfully"
  });

});

// delete method

app.delete("/deleteUser/:id", (req, res) => {

  const { id } = req.params;
  const userId = parseInt(id);

  const userIndex = users.findIndex((item) => item.id === userId);

  if (userIndex === -1) {
    return res.status(404).json({
      message: "No user found"
    });
  }

  const deletedUser = users[userIndex];

  users.splice(userIndex, 1);

  res.send(`Deleted user: ${deletedUser.name}`);

});

// Run Server on 3000

app.listen(3000, () => {

  console.log("Server running on port 3000");

});

Quick Revision

  • Static routes should be declared before dynamic routes.

  • Keep GET requests idempotent and avoid using req.body.
Why Should Static Routes Be Placed Before Dynamic Routes?
  • Express matches routes from top to bottom.
  • The first matching route is executed, and Express stops checking the remaining routes.
  • A dynamic route like /users/:id matches any value after /users/.
  • Therefore, /users/profile also matches /users/:id because req.params.id = "profile".
  • If the dynamic route is declared first, the static route /users/profile will never execute.
  • Always place static routes before dynamic routes so that specific URLs are matched first.

Interview Tip:
Express follows "First Match Wins". Since dynamic routes match any value, always define static routes before dynamic routes.

Idempotency in REST API

What is Idempotency?

Idempotency means performing the same HTTP request multiple times produces the same final result as performing it once.

Simple Definition

Sending the same request again and again should not change the final state of the resource.

Layman's Example

🔒 Locking a Door
Lock Door

↓

Door is Locked

↓

Lock Again

↓

Still Locked

↓

Lock Again

↓

Still Locked

No matter how many times you lock the door, the final state is always Locked.

HTTP Methods & Idempotency

HTTP Method Idempotent? Reason
GET ✅ Yes Only reads data and does not modify it.
POST ❌ No Creates a new resource every time the request is sent.
PUT ✅ Yes Replaces the resource with the same data each time.
PATCH ⚠ Depends Depends on implementation. Some PATCH operations are idempotent, some are not.
DELETE ✅ Yes Repeating DELETE keeps the resource deleted.

Examples

PUT (Idempotent) 
PUT /users/1

{
    "name":"Sainath"
}

Sending this request 10 times will still leave the user's name as Sainath.

POST (Not Idempotent) 
POST /users

{
    "name":"Sainath"
}

Sending this request 10 times creates 10 different users.

DELETE (Idempotent) 
DELETE /users/10

First request deletes the user. Sending it again keeps the user deleted.

PATCH (Depends)
// Example 1
{
   "age":25
}
✅ Idempotent

// Example 2
age = age + 1
❌ Not Idempotent

PATCH depends on how the update logic is implemented.

Easy Trick to Remember

Ask yourself:

"If I send the same request 100 times, will the final data remain the same?"

  • ✅ Yes → Idempotent
  • ❌ No → Not Idempotent
Interview Answer (30 Seconds)

Idempotency means sending the same HTTP request multiple times produces the same final result as sending it once. GET, PUT and DELETE are idempotent because repeating the request doesn't continue changing the resource. POST is not idempotent because it creates a new resource each time. PATCH depends on its implementation.

Understanding the next() Function

1. Should We Use the Same Keyword next?

No. The parameter name does not have to be next. You can use any valid variable name because JavaScript functions use parameter position, not the parameter name.

Interview Answer:
The third parameter passed to a middleware function is the function that transfers control to the next middleware or route handler. Although it can have any name, next is the standard naming convention used in Express.js.

2. Recommended Way

    console.log("Middleware Executed");

    next();

});

3. Custom Variable Name (Also Works)

    console.log("Middleware Executed");

    myFunction();

});
Although this works, using next is recommended because it follows the Express.js standard and makes the code easier to understand.

next() tells Express to continue executing the next middleware or route handler in the request-response cycle.

Fixed Schema vs Flexible Schema | Structured, Semi-Structured & Unstructured Data

What is a Schema?

A Schema is the structure or blueprint of a database. It defines what fields (columns) a record should contain and what type of data can be stored.

Layman Example:
Think of a school admission form. Every student must fill the same fields like Name, Age, Class, Phone Number. This predefined format is called a Schema.

1. Fixed Schema (SQL Databases)

In a Fixed Schema, every record must have the same columns. You cannot store extra fields unless you modify the table structure.

Interview Answer:
Fixed Schema means every row follows the same predefined structure.
Database Example

-----------------------------------------------------

2  | Rohith   | 23  | Java
3  | Venu     | 25  | Python

You cannot suddenly add a new field like Skills to only one student. First, you must alter the table.

2. Flexible Schema (MongoDB)

In a Flexible Schema, each document can have different fields. You don't need to define all fields in advance.

Interview Answer:
Flexible Schema allows different documents to have different fields.
MongoDB Example

Every document can contain different fields. MongoDB does not require all documents to have the same structure.

export const getStudent = async (req, res) => {
  try {
    const collection = getDB().collection("studentdb");

    if (!ObjectId.isValid(req.params.id)) {
      return res.status(400).json({ error: "Invalid student ID" });

    });

    if (!student) {

        success: false,
        message: "Student Not Found",

    res.json({
      success: true,
      data: student,
    });

    res.status(500).json({
      success: false,
      message: error.message,
    });
  }
};

1. Schema

Defines the structure of your document.

4. Middleware

Runs code before or after database operations.

Interview Ready Definitions

  • MongoDB: MongoDB is a NoSQL document database that stores data in BSON documents.
  • Why MongoDB: Flexible, scalable, fast and schema-less.
  • Mongoose: Mongoose is an ODM library for Node.js that simplifies working with MongoDB using schemas and models.

routes/studentRoutes.js
import express from "express";
import Student from "../models/Student.js";
import mongoose from "mongoose";

const router = express.Router();

// CREATE
router.post("/", async (req,res)=>{
  try{
    const student = await Student.create(req.body);
    res.status(201).json(student);
  }catch(err){
    res.status(500).json({message:err.message});
  }
});

// READ ALL
router.get("/", async(req,res)=>{
  const students = await Student.find();
  res.json(students);
});

// READ ONE
router.get("/:id", async(req,res)=>{
  if (!mongoose.isValidObjectId(req.params.id)) {
    return res.status(400).json({
      message: "Invalid ID",
    });
  }
  const student = await Student.findById(req.params.id);
  if(!student) return res.status(404).json({message:"Student not found"});
  res.json(student);
});

// UPDATE
// For both PUT and PATCH we use same findByIdAndUpdate method.

router.put("/:id", async(req,res)=>{
  if (!mongoose.isValidObjectId(req.params.id)) {
    return res.status(400).json({
      message: "Invalid ID",
    });
  }
  const student = await Student.findByIdAndUpdate(
    req.params.id,
    req.body,
    {new:true}
  );
  if(!student) return res.status(404).json({message:"Student not found"});
  res.json(student);
});

// DELETE
router.delete("/:id", async(req,res)=>{
  if (!mongoose.isValidObjectId(req.params.id)) {
    return res.status(400).json({
      message: "Invalid ID",
    });
  }
  const student = await Student.findByIdAndDelete(req.params.id);
  if(!student) return res.status(404).json({message:"Student not found"});
  res.json({message:"Student deleted successfully"});
});

export default router;
